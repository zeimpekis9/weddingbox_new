# Cloudflare R2 storage design

The foundation adds a server-side configuration reader and five blank environment entries. The reader verifies the account, bucket, explicit jurisdiction and credential presence before returning S3 client options. It selects the EU endpoint for `eu`. This verifies configuration behavior only. No R2 account, bucket, signed transfer or residency has been validated.

Migration `004_verified_uploads.sql` adds revocable event links, opaque guest grants, upload sessions and original metadata. The API sends signed PUTs to staging, verifies actual size and object identity, checks a bounded signature sample, promotes the bytes under an original key, and checks the original before returning a receipt. Test the live bucket CORS with `Content-Type` and `If-None-Match`, the signed staging PUT, conditional copy, and multipart completion before enabling event traffic. Keep staging lifecycle expiry and multipart abort rules separate from originals. Mocked storage and local PostgreSQL tests do not verify the live R2 configuration.

Private Standard buckets separated by environment. Propose EU-jurisdiction buckets, pending account/backup/host location approval. Verify recorded jurisdiction and endpoints. A location hint alone gives no residency guarantee. Use S3-compatible AWS SDK v3 on the server, region auto and jurisdiction-specific endpoint. Scoped credentials by environment and workload, kept in secrets store, never NEXT_PUBLIC. Use prefixes events/{eventId}/staging/{uploadId}, events/{eventId}/originals/{mediaId}, events/{eventId}/previews/{mediaId}/{version}, events/{eventId}/exports/{jobId}. Server generates every key. Restrict CORS to exact app origins and used PUT headers, expose ETag, disable public domains. Encryption at rest is provider-managed AES-256; use TLS and independent client-side-encrypted backups. Record host, bucket jurisdiction, backup location, key custody, retention and processor terms. ## Upload contract and failure recovery

1. Initialize from event grant and client idempotency key. Validate purpose, upload window, declared MIME/size, quota and bounded concurrent sessions. Return same session for same fingerprint, 409 for conflicting reuse. Persist state before signing. Start proposals at 25 MiB images, 500 MiB videos and 2-minute voice limit; revise from staging and venue checks. Reject zero-byte files. Accept only signature/decoder combinations proven in staging.
2. For small files issue short PUT to staging with signed required headers including If-None-Match: * if browser interoperability passes. Never reuse a staging key for a different attempt or allow a client write to originals. Require no-replay behavior in tests. If the conditional path fails certification, use a new staging key and server promotion conditional on verified source ETag, then verify destination identity. Never expose presigned server credentials. Sign only up to 5 minutes initially and issue parts in small windows. Client size declarations are untrusted and hard PUT size enforcement depends on demonstrated browser signing behavior. Apply quota reservation, verify actual sizes and promptly clean over-limit objects.
3. Use multipart at 32 MiB and above, 8 MiB parts initially, adjusted before init as needed. Server calls CreateMultipartUpload; persist upload ID or reconcile leaked init via ListMultipartUploads/lifecycle. Sign UploadPart for exact key/upload ID/part number. Browser uses XHR progress and persists metadata in IndexedDB, with safe re-selection and fingerprint verification. Abort individual network requests and let server settle cancel/finalize races. Limit each device to two files and two parts globally at first, with retries using exponential backoff, jitter and Retry-After.
4. On completion acquire a short logical lease, paginate ListParts, validate contiguous part numbers, expected lengths and returned ETags, then call CompleteMultipartUpload. Lost response triggers HEAD on the same staging key before retry. Never use ETag as SHA-256. HEAD size and identity, perform bounded signature sniff, promote from verified staging to an immutable server-owned original with conditional source identity; verify original HEAD using origin. Enforce exclusive writer/fencing and test replay while finalization runs. For objects within proposed limits, certify CopyObject with source precondition before choosing it; otherwise use a bounded conditional stream path in the worker. The API can return 202 until verification succeeds. Transactionally record UPLOADED plus one job; repeat complete returns existing receipt. No success on client PUT alone.
5. Worker streams hash and inspects parser/container limits for JPEG, PNG, WebP, HEIC/HEIF, MP4, MOV and supported voice encodings; unsupported or malformed formats quarantine. Record detected MIME, original hash, sizes and derived media. Preserve unmodified originals, create stripped thumbnails and safe playback derivatives with bounded workers. Approved READY alone becomes guest-visible. Cleanup reconciles stale sessions, aborts parts, and deletes expired staging only after lease/inventory checks. Restore a DB-lost receipt from reconciled object inventory with verified event ownership, not guesswork.

Use authorize-then-presign GET (brief TTL) with safe content disposition and no token logging. Do not share raw signed URL as gallery permalink. Honor event membership/guest scope for each read. R2 supports range reads for playback. Private originals must remain inaccessible on the public internet without a capability. Browser cache policy and signed-link exposure need tests.

## Export, backup and provider limits

Export worker captures authorized point-in-time manifest, streams original photos/video/voice and UTF-8 guestbook into ZIP64 with bounded spool or multipart output, writes counts, SHA-256, sizes and archive hash, verifies ZIP/manifest before READY, and reports byte/file progress. Owner download is short-lived after auth. Lifecycle plus janitor cleans failed/expired artifacts, never originals merely due to export expiry. Proposed export retention 24 hours; confirm original/backup retention with owners.

Use an independent provider/account with separate credentials, encryption and immutable retention where supported. Copy originals plus manifests and hash-check. Restore into isolated bucket and database; test playback and file integrity, retaining the only good copy through any rollback.

R2 Standard published rates are $0.015/GB-month, $4.50/million Class A, $0.36/million Class B, no internet egress charge. Monthly free tier is 10 GB-month, 1M A and 10M B. Illustrative 100 GB-month and requests within free tier costs $1.35 in R2 storage, excluding compute, backup, taxes and other account usage. Estimate workload with staging/original coexistence, multipart requests, HEAD/GET, preview and export bytes and alarms. R2 allows up to 10,000 parts, 5 MiB–5 GiB per part (last can be smaller), equal nonfinal size, max object about 4.995 TiB and a per-key write limit of one per second. Document observed account quotas. Incomplete multipart auto-aborts after seven days by default; set tested lifecycle backstop plus app cleanup. No custom-domain presigned URLs or presigned form POST.

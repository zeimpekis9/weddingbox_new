# Migration roadmap for approval

Guests can scan the QR, select photos and videos immediately, and receive a durable upload receipt. Owners retain existing event data and guestbook behavior, with private access and verified recovery. Approved decisions are R2, self-hosted PostgreSQL, complete Supabase removal, no guest accounts, and single-event operation with enforced multi-event boundaries.

All paths below are repo-relative. New paths are proposed. Add tests against a disposable DB and R2 staging with synthetic data before switching callers. Keep Supabase resources and isolated source backups until explicit decommission approval.

## Decisions for approval

1. Confirm Linux Compose host/domain/TLS ownership, deployment operator, downtime budget, and single-host recovery target. Approve a compatible supported Next release within the existing framework.
2. Confirm R2 jurisdiction, independent backup destination/region/key custody, retention, budget and proposed RPO/RTO. R2 and self-hosted PostgreSQL are settled choices.
3. Approve read-only access to live Supabase inventory and restricted migration rehearsal, plus two owners, moderator permissions and initial gallery/display sharing policies. Assign authority to resolve legacy exceptions.
4. Approve production cutover window only after parity, browser/security tests, venue rehearsal, measured capacity, manifest reconciliation and restore. Separately approve any source decommission.
